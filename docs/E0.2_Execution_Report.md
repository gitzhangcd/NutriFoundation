# E0.2 Execution Report

## Objective

Implement persistence, NCBI connectors, RunManifest, SourceArtifact ingestion and deterministic Batch001 replay while preserving E0.1 scientific governance.

## Implemented

### Persistence

SQLite reference store now persists:

- RunManifest
- SourceArtifact
- PMC full-text XML
- ingestion events

Serialized SourceArtifact payloads and PMC XML receive SHA-256 digests.

### RunManifest

Every ingestion run now creates a RunManifest before retrieval and updates it to completed/failed after execution.

Completed manifests are immutable by code guard.

Each ingested SourceArtifact also stores the run_id inside provenance metadata, in addition to the database ingestion-event link.

### Connectors

Implemented live NCBI connectors:

- PubMed `efetch` XML retrieval and parsing
- PMC `efetch` full-text XML retrieval

The parser preserves PMID, DOI, PMCID, title, journal, publication date, authors, publication type and abstract.

### CLI

Added:

```bash
nutri init-db
nutri ingest-pmid
nutri fetch-pmc
nutri replay-batch001
```

Replay supports both deterministic offline fixture mode and live NCBI mode.

## Network-test limitation

The execution container used for local validation could not resolve public internet hosts. Therefore the new HTTP client was not locally exercised end-to-end against live NCBI from the container.

This limitation is isolated by design:

- PubMed parsing/request behavior is unit-tested;
- deterministic replay is network-independent;
- the Batch001 fixture derives its identifiers from the authoritative verified registry;
- live connector mode remains available for production/CI environments with network access.

No live-network success is claimed in this report.
