# E0.3.1 Execution Report

## Objective

Freeze a provider-portable semantic worker boundary so the current ChatGPT chat window can perform semantic inference while deterministic scientific logic remains executable code.

Target architecture:

```text
Code
  ↓
TaskBundle
  ↓
Semantic Worker
  ↓
ResponseEnvelope
  ↓
Code
  ↓
EvidenceExtractionCandidate
  ↓
Independent Verification
  ↓
F0 Freeze
```

## Implemented

### Provider-neutral domain contracts

Added:

- `TaskBundle v0.1`
- `ResponseEnvelope v0.1`
- `WorkerDescriptor`
- `SemanticSubmissionReceipt`
- deterministic `SemanticTaskState`

### Chat-window bridge

Implemented `ChatWindowFileBridge`.

It exports:

```text
TASK.request.json
```

and imports:

```text
TASK.response.json
```

The bridge contains no scientific verification and no F0 authority.

### Provider portability

Added `SemanticWorkerAdapter` protocol:

```python
class SemanticWorkerAdapter(Protocol):
    adapter_type: str
    def execute(self, task: TaskBundle) -> ResponseEnvelope: ...
```

Added `run_adapter_conformance()`.

A future provider is accepted only when its ResponseEnvelope:

- uses the adapter's declared adapter_type;
- binds to the exact task ID;
- binds to the exact task SHA-256;
- binds to the exact source-text SHA-256;
- preserves contract version;
- preserves response schema version.

### Deterministic orchestration

Implemented semantic task states:

```text
PENDING
  ↓
EXPORTED
  ↓
RESPONDED
  ├─> DEFERRED
  ├─> REJECTED
  ↓
INGESTED
  ↓
F0_FROZEN
```

Illegal transitions are rejected.

### Response ingestion

A completed ResponseEnvelope is not evidence.

The core engine first performs:

1. TaskBundle binding;
2. response field allowlist validation;
3. deterministic mapping to EvidenceExtractionCandidate;
4. IndependentEvidenceVerifier;
5. F0FreezeEngine.

Therefore:

```text
ResponseEnvelope != EvidenceUnit_F0
```

### Defer semantics

The semantic worker may return `defer`.

This creates no EvidenceUnit and no F0 object.

```text
SemanticUncertainty -> DeferAllowed
```

### Persistence

Added:

- `semantic_task`
- `semantic_response`
- `semantic_event`

Task and response payloads are immutable.

Mutable execution state is stored separately from immutable TaskBundle content.

### CI attempt 2

Two issues were detected.

#### Version smoke test drift

The engine was intentionally bumped to `0.3.1`, while an older smoke test still expected `0.3.0`.

Resolution:

The version test was updated to the new frozen engine version.

#### TaskBundle canonical hash mismatch

The first TaskBundle implementation hashed pre-validation Python object representations.

Pydantic-normalized JSON could differ for values such as:

- datetime;
- Pydantic models;
- tuple/list representations.

This produced legitimate task-hash mismatches.

Resolution:

TaskBundle now:

1. constructs the normalized model representation;
2. serializes to Pydantic JSON form;
3. computes SHA-256 over canonical normalized JSON;
4. validates future loads against the same representation.

The task-hash invariant was preserved and strengthened; it was not bypassed.

## Provider migration guarantee

The frozen engineering rule is:

```text
Provider-specific logic lives only in an adapter.
```

Migration from the chat-window bridge to an API/local model requires:

1. implement `SemanticWorkerAdapter.execute(TaskBundle)`;
2. return `ResponseEnvelope`;
3. pass `run_adapter_conformance()`.

The following are not allowed to change solely because of provider migration:

- TaskBundle schema;
- ResponseEnvelope schema;
- EvidenceUnit schema;
- response binding;
- deterministic verifier;
- F0 freeze engine;
- persistence semantics;
- ScientificClaim pipeline;
- GOLD governance.
