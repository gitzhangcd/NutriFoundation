# E0.3｜Evidence Extraction Agent, Independent Verification, EvidenceUnit Persistence, F0 Freeze Engine & Batch001 Evidence Replay

## Status

`REFERENCE IMPLEMENTATION / EXECUTABLE CONTRACT FREEZE`

## Scope

E0.3 converts the existing SourceArtifact layer into an executable EvidenceUnit production pipeline:

```text
SourceArtifact
    +
SourceTextSnapshot
    ↓
EvidenceExtractionCandidate
    ↓
Independent Evidence Verification
    ↓
F0 Freeze
    ↓
EvidenceUnit_F0
```

E0.3 does not create ScientificClaim GOLD and does not replace F1 full-text methodological review.

## Authority boundary

Current F0 policy follows `Batch001_EvidenceUnit_Verification_Queue_v0.1.yaml v0.3`:

- F0 may be frozen after independent Agent verification.
- Human review is not mandatory for F0.
- F1 critical methodological fields require human/expert review.
- ScientificClaim/Decision GOLD requires independent human/expert adjudication.

This supersedes the original v0.1 annotation-manual statement that all EvidenceUnit freezing required Human Audit.

## Evidence Extraction Agent contract

The core engine is model-provider agnostic.

`EvidenceExtractionAgent` accepts any provider implementing the structured extraction interface.

Reference implementations:

- `FixtureEvidenceExtractionProvider` — deterministic regression only; never scientific authority.
- `SubprocessEvidenceExtractionProvider` — external JSON command adapter for a live LLM/agent.

The external provider receives:

- SourceArtifact metadata;
- source text;
- evidence_id;
- frozen E0.3 extraction rules.

It must return a structured EvidenceUnit candidate plus extraction confidence.

## Candidate invariants

Every EvidenceExtractionCandidate records:

- candidate_id;
- EvidenceUnit candidate payload;
- extractor identity;
- extraction method;
- extraction confidence;
- source-text SHA-256;
- creation time;
- RunManifest provenance.

Candidate is not frozen evidence.

## Independent Verification contract

The verifier is deterministic and separate from the extractor.

F0 verification checks:

1. exact source linkage;
2. matching source-text hash;
3. required scientific fields;
4. source anchor presence;
5. numeric effect support in source text;
6. applicability boundary presence;
7. observational-association causality guard;
8. guideline/consensus authority guard;
9. extractor/verifier identity separation.

A verification result is one of:

- `verified`
- `rejected`
- `escalate`

A rejected record is retained for audit.

## Numeric support guard

Numeric values appearing in the extracted effect/recommendation are normalized and compared against numeric tokens present in the source text.

If an effect contains an unsupported number, F0 verification fails.

This guard is intentionally conservative and does not claim to replace semantic scientific review.

## Observational causality guard

Observational/cohort evidence must remain explicitly encoded as association-level evidence.

```text
ObservationalAssociation != CausalEffect
```

Citation count, journal visibility or model confidence cannot override this rule.

## Guideline authority guard

Guideline/consensus sources may generate source-stated recommendation EvidenceUnits.

They must not be encoded as independent causal effect estimates merely because the recommendation is authoritative.

Recommendation-type EvidenceUnits are allowed to omit an empirical outcome field when the source object is a guideline/consensus statement.

## F0 Freeze contract

F0 freeze requires:

- verified EvidenceVerificationRecord;
- same candidate/evidence identity;
- same source-text hash between candidate and verifier;
- all required verification checks true;
- zero verification errors.

F0 freeze creates:

- immutable EvidenceUnit_F0 payload;
- F0FreezeRecord;
- explicit lineage to candidate and verification objects;
- RunManifest-linked persistence.

## Persistence

E0.3 adds:

- `source_text_snapshot`
- `evidence_candidate`
- `evidence_verification`
- `evidence_unit_f0`
- `evidence_event`

Frozen F0 payloads are immutable. Silent overwrite is prohibited.

## Source text precedence

Default live precedence:

1. persisted PMC full text;
2. persisted PubMed abstract.

Offline Batch001 replay uses a dedicated regression-support fixture generated from the frozen registry. That fixture tests pipeline/state/payload preservation only and is explicitly not scientific authority.

## Batch001 replay

The deterministic E0.3 replay executes:

```text
20 SourceArtifacts
    ↓
20 EvidenceExtractionCandidates
    ↓
20 independent verification records
    ↓
20 F0 freezes
    ↓
payload comparison with authoritative Batch001 F0 registry
```

Pass criteria:

- expected EvidenceUnits = 20;
- stored F0 EvidenceUnits = 20;
- payload matches = 20;
- mismatch count = 0;
- evidence pipeline RunManifest = completed.
