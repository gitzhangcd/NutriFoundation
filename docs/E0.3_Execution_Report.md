# E0.3 Execution Report

## Objective

Implement an independently runnable EvidenceUnit production layer:

```text
SourceArtifact
→ Evidence Extraction Candidate
→ Independent Verification
→ EvidenceUnit F0
```

and replay all 20 frozen Batch001 EvidenceUnits through the executable pipeline.

## Implemented

### Evidence Extraction Agent

Added:

- `EvidenceExtractionAgent`
- `FixtureEvidenceExtractionProvider`
- `SubprocessEvidenceExtractionProvider`

The engine is model-vendor agnostic. A live extractor can be attached as any external command that consumes/returns the frozen JSON contract.

### Independent Evidence Verifier

Implemented deterministic checks for:

- source identity and source-text hash;
- required fields;
- source anchor;
- numeric support;
- applicability boundary;
- observational causality guard;
- guideline/consensus authority guard;
- extractor/verifier identity independence.

### F0 Freeze Engine

Implemented:

- verified-only freeze;
- candidate/verification identity consistency;
- source-text hash consistency;
- immutable F0 persistence;
- F0FreezeRecord lineage.

### Persistence

Added persistent tables for:

- source text snapshots;
- evidence candidates;
- evidence verification records;
- F0 EvidenceUnits;
- evidence pipeline events.

PubMed abstracts are now persisted during SourceArtifact ingestion. PMC XML is also exposed through source-text selection when available.

### CLI

Added:

```bash
nutri produce-evidence
nutri replay-evidence-batch001
```

### Workflow schemas

Frozen:

- `EvidenceExtractionCandidate v0.1`
- `EvidenceVerificationRecord v0.1`
- `F0FreezeRecord v0.1`

The Schema Registry and Data Lineage Policy were updated accordingly.

## Batch001 replay debugging history

The first remote E0.3 CI run produced:

```text
26 passed
1 failed
17/20 F0 EvidenceUnits reproduced
```

The missing records were exactly:

- EU-B001-015 — ADA consensus
- EU-B001-016 — KDOQI guideline
- EU-B001-017 — ESPEN geriatric guideline

Root cause:

The Python EvidenceUnit model still required an empirical `outcome` for every EvidenceUnit. That assumption was valid for empirical RCT/cohort/meta-analysis records but invalid for source-stated guideline/consensus recommendation objects.

The implementation was corrected so that:

- effect-based EvidenceUnits still require outcome;
- recommendation-type EvidenceUnits require population + recommendation but may omit empirical outcome;
- guideline/consensus authority guard remains mandatory.

No verification rule was relaxed to force replay success.

## Scientific non-regression result

E0.3 preserved all critical boundaries:

- no observational association was promoted to causal evidence;
- no unsupported numeric effect can pass F0;
- no guideline statement is treated as an independent causal effect estimate;
- extractor and verifier must be independent for verified status;
- F0 remains distinct from F1 and GOLD;
- existing Batch001 Gold state remains 0.

## Important limitation

The deterministic Batch001 Evidence replay uses the already-frozen registry as the extraction regression fixture. It validates pipeline behavior, state transitions, immutability, verification guards and payload preservation.

It does **not** constitute an independent scientific re-extraction of all 20 papers from raw full text.

The live path is implemented through `SubprocessEvidenceExtractionProvider`, but a specific production LLM/model adapter has not yet been frozen in E0.3.
