# A2.6-P1 科学语义裁定与独立专家审核规范 v0.1

状态：工程准备完成前不得派发或解盲。P0 审计收据为上位约束；本规范不修改原 A2.5 参考、A1 检索或 score_a2.py。

## 1. 科学判断单位与规范

每个案例为原生食物/菜肴记录，不是患者或实测样本。八维度分开核验；SOURCE_EXPLICIT 必须能定位原生字段且仅陈述字段明确表达的事实，SEMANTIC_INFERENCE 必须注明推理及限制，EXTERNAL_SUPPORTED 必须有可核验外部证据且不从目标概念反推来源事实；UNRESOLVED 保留 null。参考食谱列举不代表实际组成、重量或营养含量。缺失不等于否定。

关系方向始终 SOURCE_RELATION_TO_TARGET。EXACT 要同一概念粒度及决定身份的限定条件一致，不能把概念等价当成测量等价；CLOSE 为近似但不可替代；BROADER_TARGET 为目标外延更广；NARROWER_TARGET 为目标外延更窄、需额外特异条件；RELATED 仅相关；CONDITIONAL 必须列明待满足条件且 CONDITIONAL_CONCEPT_CANDIDATE；AMBIGUOUS/UNRESOLVED 不计支持。方向与适用性不一致须另记争议，不静默改原记录。概念层不授权营养成分迁移；measurement_transfer=HOLD。

困难负例须有双侧证据、明确冲突轴和可复查的理由。EXPLICIT_CONFLICT、GRAIN_OR_ROLE_DIFFERENCE、COMPOSITION_OR_SPECIES_DIFFERENCE 仍须专家确认；不是自动真值。TARGET_SPECIFIC_CONDITION：条件明确不满足方可裁定负例；条件未知时 REVIEWED_UNRESOLVED。UNRESOLVED_OTHER 不可作为已证实科学错误。未检索/未审阅与已审阅未定性分离；未命中有限搜索不代表标准库不存在目标。

P0 的 131 个标记不是 131 个已证实错误：88 条目标条件负例、1 条未解决负例、3 条关系与 RELATED_ONLY 不一致、36 个敏感推断、3 个目标支持来源维度。其优先级为未解决负例及条件负例 -> 关系/适用性 -> 敏感推断与反向来源推断。所有 32 例均保留。

## 2. 两条路线，等待 PI 选择

D02-A（建议，先完成开发检索评价）: 原 32 例和原冻结评分定义作为主分析，仅称 AGY critic reference overlap。原负例重叠仅称“评审者标记的困难负例重叠”，不是错误率、安全性或精确率。保留原非 RELATED/RELATED_ONLY 敏感性。另预先规定保守次要敏感性：将原 TARGET_SPECIFIC_CONDITION 和 UNRESOLVED_OTHER 负例（合计89）转为已审阅未定性；不新增支持边、不丢失已审阅成员，并同时使用原 sensitivity=True 排除 RELATED/RELATED_ONLY。其余负例仍只是评审者标记，不是专家真值。次要投影不符合原科学记录 Schema 的候选上限，不是新的科学参考，不修改文件。三组报告分别标记 RAW_PRIMARY、RAW_NONRELATED、CONSERVATIVE_SECONDARY；主指标始终原定义，不择优替换。没有资格支持临床或科学映射发布。

D02-B（先专家裁定）: 完成 Phase A 独立源资料审核及 Phase B 原 AGY 裁定，另版本冻结 overlay 和分歧解决，保留原主分析。该路线暂不由本版真实导入器放行；需新的门禁版本及裁定收据，避免将任意专家意见当成已验证 Gold。

## 3. 专家任务（本轮仅准备）

Phase A: PI 指派具备食品科学/营养学/食品本体经验且与被评价检索方法开发无利益冲突的独立专家。只提供原 source-only packet、四份固定标准资料和原任务规则/响应 Schema；不提供 AGY 参考、P0 风险标签、候选排序、检索结果或旧评审。逐例独立提出概念关系、条件、困难负例及不确定性，独立输出及带身份/资质/暴露声明的签名收据，按原 Schema 记录 CRITIC_DRAFT，不自动称 Gold。源资料权限/权属和任务隔离先核验。冻结 Phase A 之后才能进入 Phase B。

Phase B: 专家读取同一来源、原标准和冻结 AGY 记录，使用本地队列的 ordinal/field/index；逐例每个维度与每条边 ACCEPT/REVISE/UNRESOLVED/ABSTAIN，双侧证据索引、明确理由、对原始判断的分歧及建议。REVISE 仅写单独建议对象，不修改原记录；不赋予发布或营养转移权。未知可明确保留，不强制映射。已核验所有队列成员才能称完整；签名、身份和专家资质须由 PI 核实。独立第二位专家/仲裁者处理科学分歧与高风险边后才考虑 Gold，不能仅用模型一致性替代。当前无专家指派或派发。

## 4. 需要人工确认的权属及科学决策

D01：数据权属责任人能否基于有据可查的许可/协议/合法使用依据确认 32 例 NutriData 来源及引用的标准允许本地 CURATION_DEV 检索重叠评价？记录授权主体、依据、范围、期限/限制、责任人；不能由工程负责人单纯声明替代；未确认则 HOLD。之前 AGY 执行许可不等于数据许可，历史外部处理权属/隐私问题仍需核查。禁止未经授权发布、商业使用、转交第三方或公开原始记录。若无可确认依据，停止真实比较，改用合规来源需新队列和方法冻结。

D02：选择 A 或 B。A 仅为开发参考重叠，不是科学 Gold；B 为更强的科学参考路线，专家真实审核及仲裁是另外的任务。

D03：若启动专家工作，确认具体专家/机构、资质、利益冲突、资料可访问权限及本地隔离流程。若选 A，可以明确暂缓专家，不视作专家已完成。科学发布仍 HOLD。

D04：待 D01/D02 决定、版本化决策与工程验收完成后，PI 另行授权具体不可变导入运行。此次 P1 不是解盲授权。导入会打开真实排名，必须另行授权；其输出仅为本地封存的合法导入包，不自动计算真实指标；之后 P2 评分须独立授权并绑定同一导入包。权属确认和语义选择不得被当作自动 D04。

## 5. 审核交互模板（现场使用，非已填写）

每例先显示原生来源和固定标准证据位置，Phase A 不显示 AGY 或风险标签；记录独立判断后冻结。Phase B 每个项目显示原判断及源/目标证据，选择接受/修订/未解决/弃权、原因代码、证据及拟修订字段。记录原始八维度、候选及困难负例的全量关闭情况；保留每个未解决项。每份结果绑定 source-only freeze SHA、原 reference_record SHA、案例序号、审阅者身份、签名及无排名访问声明。JSON 模板由独立 Schema 约束；正式入库另须精确队列闭合、证据真实性和签名/权限校验。模板不是已建成的专家网站或已运行的人工审核系统。
