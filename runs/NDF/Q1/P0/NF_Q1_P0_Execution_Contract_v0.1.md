## 1. Aim
Construct a question-conditioned scientific bridge:
SourceArtifact / StudyIdentity -> EvidenceUnit / ScientificClaim -> **Source-Derived UserQuestionCandidate** -> Question–Claim–Evidence link -> Answerability Assessment -> Expert factual review -> versioned Question/Answer Contract.

**No paper -> single answer shortcut**. A source may generate many questions without being able to answer them. A user question may require multiple independent studies or clinical context.

## 3. Extraction & review operating mode
A. Source admission: use source identity, byte/content provenance, access and rights gate. `RELEASE_FOR_EXTRACTION` allows internal development, not expert Gold or public distribution.
B. Read source once where qualified; produce StudyCard, EvidenceUnit, ScientificClaim, related research question + user question proposals + boundaries.
C. Independent machine verifier returns source anchors, numeric/context discrepancy and abstention; must not self-certify L3/L4. In current P0 **reuse upstream A2 L1/L2**; no new separate checker was executed.
D. Group drafts by common *fact to verify*, not by question count. One human source check can be reused by related drafts, but answerability and clinical applicability remain **question-specific**.
E. Expert action: ACCEPT / MODIFY / REJECT / NEEDS_EVIDENCE / NOT_APPLICABLE; always record raw pre-edit draft, source location, expert identity/role, exposure to AI, rationale, review time, affected objects, revision and adjudication if necessary.
F. Promotion after review: L3 semantic scope and L4 question-specific qualification separately. No inference from `L1=L2=PASS` to `Gold=true`.
G. Source-grounded user-answer text remains a **candidate**; no RAG gold benchmark or user-facing recommendation is generated by this P0.

## 4. Object semantic boundaries
- `question_origin=SOURCE_DERIVED_SIMULATED_USER_VOICE` is a *synthetic demand hypothesis*, never a sampled real-user query.
- `candidate_answer_zh` is a draft bounded to study-level reporting; null means no defensible answer within this slice.
- `answerability_candidate` options: STUDY_BOUNDED, PARTIAL_BOUNDARY, UNANSWERABLE_CURRENT_SLICE, EXPERT_CLINICAL_REQUIRED. Status may change ONLY via explicit scientific review/new evidence.
- `claim_refs` may be empty (question maps to EvidenceUnit, or asks an unsupported question). Do not invent claim links to fill schema.
- `source_gate`, `evidence_L1/L2`, `semantic_L3`, `qualification_L4`, and `expert_review` are separate; never compress to `verified:true`.
- Observational association != intervention causal effect. Trial completer result != guaranteed individual benefit. Short-term no reported SAE != long-term safety. Unmeasured mechanism != established mechanism.
- Question generation and answer constraint **are different tasks**: exact study question relevance does not qualify a personalized answer.
- Reference independence: this Agent-visible curation workflow is not blind de-novo expert Gold. Capture AI exposure. Future gold/evaluator requires an independently governed information projection and review design.

## 7. Metrics and science
- Expert burden: active human minutes, rejected/modified items, 10 packets vs 16 question drafts; units verified per active expert hour.
- Source fidelity: numeric mismatches, unit errors, population/comparator mismatch, unsupported causal claims, ambiguous anchor errors, critical safety omissions.
- Demand validity: user-realism rated independently, duplicate/paraphrase family and coverage against real-user question sample (not available yet).
- Answerability: study-bounded/partial/insufficient/expert-clinical precision and abstention rate against independently adjudicated labels; measure error not number of generated Q/A.
- Zero critical wrong promotions; report denominator and uncertain items. Any early performance claim is **descriptive only**, not proof Agent-first superior.
